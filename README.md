# Steam 好友视奸器 / Steam Friend Monitor

> 一个带图形界面和系统托盘的 Steam 好友活动监控工具。
> 除了常规的「谁在线 / 在玩什么」，它还能追踪**好友的游戏时长变化**、**把游戏设为私密的行为**，以及**家庭共享游戏和免费软件**的游玩时长。

版本：**v2.5.0** ｜ 语言：中文 / English ｜ 平台：Windows

## 为什么写这个

Steam 官方客户端只能看到好友「当前」的状态，看不到历史。而现成的监控方案要么是命令行工具，要么是聊天机器人插件，对普通用户不够友好；更重要的是，它们几乎都忽略了一类很有意思的信息——**好友试图隐藏自己在玩什么**。

这个项目的出发点就是：把 Steam Web API 能挖出来的信息做到尽可能完整，并且用一个普通人能直接双击运行的方式呈现出来。

## 功能特性

### 状态监控
- 监控好友的在线状态：在线 / 忙碌 / 离开 / 打盹 / 想交易 / 想玩游戏 / 离线
- 特殊处理「离开但正在玩游戏」的组合状态，显示为 `游戏中(离开) - 游戏名`
- 状态发生变更时记录到 CSV 并实时输出到日志区
- 连续多次获取不到数据时告警（可能被移出好友或设为私密）

### 游戏时长监控
- 追踪每位好友每款游戏的**累计总时长**变化，并计算每次的**增量**
- 首次记录某款游戏时单独标记
- **隐私检测**：当一款原本可见的游戏从好友列表中消失，判定为「被设为私密」并告警；重新可见时记录「取消私密」
- 覆盖**家庭共享游戏**和**免费软件**（详见[设计亮点](#设计亮点)）

### 使用体验
- **图形界面**（tkinter），左右可拖动分栏：左侧好友状态表，右侧实时日志
- **系统托盘**：最小化/关闭可缩到托盘，左键双击恢复窗口，托盘菜单支持立即刷新、打开设置
- **关闭行为可选**：缩到系统托盘（默认）或直接退出
- **中英双语**，可在设置中随时切换，无需重启
- **游戏名称映射**：自动记录 API 返回的游戏名，同时允许手动改名覆盖；支持右键快速重命名
- **追踪筛选**：好友很多时可以只勾选关心的几位
- 每个好友的状态与时长记录分别写入独立 CSV，可右键查看

## 设计亮点

这一节记录几个关键的技术设计决策，也是这个项目相比同类工具主要的不同点。

### 1. 为什么要合并两个 API 数据源

最初只用 `IPlayerService/GetOwnedGames` 拉取时长，但在实际使用中发现两类游戏**永远不会被记录**：

| 场景 | 原因 |
|---|---|
| 好友通过**家庭共享**玩的游戏 | `GetOwnedGames` 只返回玩家**自己拥有**的游戏，共享来的游戏不属于他，不会出现在返回结果里 |
| **免费软件**（如 OBS） | `GetOwnedGames` 即使加上 `include_played_free_games=true`，覆盖的也只是免费**游戏**，不含免费**软件** |

解决方案是额外调用 `IPlayerService/GetRecentlyPlayedGames`（返回最近两周玩过的应用，**包含共享游戏和免费软件**），把两个来源按 `appid` 合并去重、总时长取较大值。

```python
# 数据源 1：拥有的游戏（稳定，覆盖付费+免费游戏）
# 数据源 2：最近玩过的应用（补充家庭共享游戏、免费软件）
# 合并时给每条记录打上 source 标记：owned / recent
```

> 局限：`GetRecentlyPlayedGames` 只覆盖最近两周。超过两周没碰的共享游戏仍无法捕获——这是 Steam API 的固有限制。

### 2. 隐私检测为什么要区分数据来源

上一步引入了一个副作用：共享游戏会在两周窗口后**自然地**从数据里消失。如果沿用「历史里有、当前没有 = 被设为私密」的判断，就会对共享游戏产生大量误报。

因此合并数据时给每条记录打上 `source` 标记，隐私检测**只对 `source == 'owned'`（真正拥有的游戏）触发**：

```python
for appid in history_appids - current_appids:
    # 只有「拥有的游戏」消失才视为设为私密；
    # 「最近游玩」来源的共享游戏会随两周窗口自然消失，静默跳过
    if old_entry.get('source', 'owned') != 'owned':
        continue
    ...
```

### 3. 游戏名称映射：自动写入 + 手动优先

`GetOwnedGames` 默认**不返回游戏名称**，必须显式加 `include_appinfo=true`。修复之后，程序会把拿到的游戏名自动写入 `game_names.json`，但遵循一条规则：

**映射文件里已有的非空名称优先，自动写入绝不覆盖它。**

这样既省去了手动维护几十个游戏 ID 的麻烦，又保留了随时自定义命名的能力。

### 4. 性能取舍

- 好友的游戏时长是**并发拉取**的（线程池，最多 8 路），避免好友多时逐个等待
- 游戏名称映射的写入是**批量一次完成**的，而不是每款游戏读写一次文件
- 界面文本走统一的 `t(key)` 翻译函数，语言切换时重建界面而非重启程序

## 快速开始

### 方式一：下载免安装版（推荐给非开发者）

前往本仓库的 **[Releases](../../releases)** 页面，下载最新版本的
`SteamFriendMonitor-vX.X.X-windows-x64.zip`，解压后直接双击 `SteamFriendMonitor.exe` 即可运行。

- 无需安装 Python 或任何依赖
- 解压得到的文件夹里**不含任何个人数据**，首次运行时会在 exe 同级目录自动生成 `config.json` 等文件
- 请保持整个文件夹完整（`SteamFriendMonitor.exe` 与 `_internal` 目录必须放在一起）

### 方式二：从源码运行

#### 环境要求

- Windows（其他系统未测试，理论上 tkinter + pystray 跨平台可用）
- Python 3.8+（推荐 3.10+）
- 一个 **Steam Web API Key**：在 <https://steamcommunity.com/dev/apikey> 免费申请
- 你的 **SteamID64**（17 位数字，可在 Steam 个人资料页获取）

#### 安装

```bash
pip install -r requirements.txt
```

> 如果 `import tkinter` 报错，说明 Python 安装时没勾选 tcl/tk，重新运行安装程序并勾选 **tcl/tk and IDLE**。

#### 运行

```bash
python steam_monitor.py
```

首次运行会弹出设置窗口，填入 API Key 和 SteamID64 即可。也可以手动复制模板：

```bash
copy config.example.json config.json
```

### 首次配置步骤

1. 申请 Steam Web API Key（链接见上）
2. 确保你的 Steam 隐私设置中「好友列表」为公开
3. 启动程序 → 设置 → 填入 API Key 与 SteamID64 → 保存
4. 程序自动加载好友列表，默认全部追踪；可在「追踪设置」里只勾选想看的
5. 右键某个好友可查看其状态记录与时长记录

## 数据文件说明

程序所有数据都保存在**程序所在目录**（打包后是 exe 同级目录），便于整包携带。

| 文件 | 内容 | 是否含个人数据 |
|---|---|---|
| `config.json` | API Key、SteamID、刷新间隔、语言、关闭行为 | ⚠️ **是** |
| `tracked_friends.json` | 追踪的好友 SteamID 列表 | ⚠️ **是** |
| `playtime_history.json` | 各好友各游戏的历史时长与可见性 | ⚠️ **是** |
| `logs/*.csv` | 每位好友的状态/时长变更记录 | ⚠️ **是** |
| `game_names.json` | 游戏 ID → 名称映射 | 否（仅游戏名） |
| `debug.log` | 调试日志 | ⚠️ 可能含昵称 |

> **这些文件都已在 `.gitignore` 中排除，不会进入版本库。**

## 工作原理

### 使用的 Steam Web API

| 接口 | 用途 |
|---|---|
| `ISteamUser/GetFriendList` | 获取好友列表 |
| `ISteamUser/GetPlayerSummaries` | 获取好友状态（在线状态、正在玩的游戏），每批最多 100 人 |
| `IPlayerService/GetOwnedGames` | 获取好友拥有的游戏及总时长（`include_appinfo=true` 取游戏名）|
| `IPlayerService/GetRecentlyPlayedGames` | 获取最近两周玩过的应用（补充共享游戏、免费软件）|

`playtime_forever` 字段单位为**分钟**，程序内部换算为小时展示。

### 状态判定逻辑

```
personastate: 0 离线 / 1 在线 / 2 忙碌 / 3 离开 / 4 打盹 / 5 想交易 / 6 想玩游戏
若存在 gameextrainfo（正在玩游戏）：
    离开、打盹 → "游戏中(离开) - 游戏名"
    其他状态   → "游戏中 - 游戏名"
```

### 时长变化判定

- 某游戏首次出现且时长 > 0 → 记录「首次记录总时长 X 小时」
- 与上次记录相差 > 0.5 分钟 → 记录增量变化
- 首次运行（历史为空）时不产生增量告警，避免把历史时长当成新增

## 常见问题

**Q：为什么有些游戏明明在玩，却没有时长记录？**
A：三类情况——① 好友把该游戏设为私密；② 是家庭共享游戏且**超过两周**没玩（`GetRecentlyPlayedGames` 覆盖不到）；③ 好友的「游戏详情」隐私设置为私密。程序已在能力范围内尽可能覆盖前两类。

**Q：为什么游戏名显示成「游戏ID:xxx」？**
A：说明 API 和映射文件里都没有这款游戏的名称。程序会把缺失的 ID 记录到 `game_names.json`，你可以手动补上，或右键重命名。

**Q：会不会把好友的隐私数据上传到什么地方？**
A：不会。程序只做本机读写，所有数据都保存在本地文件里，不发送到任何第三方服务器。你填的 API Key 也只用于调用 Steam 官方接口。

**Q：刷新间隔设多少合适？**
A：默认 60 秒。Steam Web API 有调用频率限制，不建议低于 30 秒，尤其是好友数量多的时候。

## 隐私与合规

- 本工具仅使用 **Steam 官方公开的 Web API**，读取的是好友**自愿公开**的信息（受其个人隐私设置约束）。
- 程序**不存储任何 Steam 账号密码**，不进行任何账号登录操作。
- 所有数据仅保存在**本机**，作者不收集、不上传任何用户数据。
- 请遵守 [Steam Web API 使用条款](https://steamcommunity.com/dev/apiterms) 及当地法律法规，仅将此工具用于**个人合理用途**，不要用于骚扰、跟踪或其他侵犯他人隐私的行为。
- 若你被他人用此工具监控而不适，可通过 Steam 隐私设置限制信息可见性。
